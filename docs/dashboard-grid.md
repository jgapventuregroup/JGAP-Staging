# Individual dashboard boxes

Owner-approved October 28, 2026. The dashboard now uses GridStack 14.0.0 (pinned dev dependency, public assets bundled locally, MIT notices retained). Five independent widgets: Deal Analyzer, Saved Properties, property count, recent properties and upcoming follow-ups. Property rows and navigation tabs remain governed by their normal data/navigation order.

Select **Arrange dashboard · Pro** to show handles. Hold a Move handle, drag a box with the left mouse button or touch, and release into the highlighted destination. Other boxes make room. Changes save automatically. Click one Move handle and then another to place the selected box before the second; this provides a click/tap alternative without a design form. Alt+arrow on a focused handle also changes position. Done exits arrangement; Undo appears after a saved change; Reset layout restores defaults. Width, visibility and position fields are not exposed. Failed writes restore the last verified geometry and offer Retry save. An accepted write that cannot be verified blocks more saves and offers Try again to safely reload. Done remains available after a verification failure. Changing accounts/workspaces clears the layout controller and pending callbacks.

`dashboard_preferences.grid_layout` is additive. `get_dashboard_grid` and `save_dashboard_grid` are security-invoker RPCs using existing user/workspace/Pro/seat RLS. Legacy section order/visibility are retained, converted on read if customized and never deleted. The default legacy layout becomes the new default grid. Save compares the previous timestamp to prevent an older browser tab silently overwriting a newer layout. JSON permits exactly five known IDs and bounded integer geometry/boolean visibility, with at least one visible box; HTML, names, notes and financial data are rejected. The browser only calls `grid.save(false)` and whitelists geometry fields. All public code is local; no new third-party runtime network request or billing account is introduced.

Narrow containers stack into a single column. Content determines box height; box widths are managed by the app; manual resizing is not exposed. Desktop geometry is cached by GridStack across responsive changes. Physical-phone/assistive-technology acceptance is distinct from simulated/unit tests.

Canonical empty-environment installation: baseline → dashboard-customization.sql → dashboard-grid.sql (plus other approved feature add-ons). Keep the old API for rollback; do not drop/reset preferences, property records or subscriptions. A frontend rollback to the old section module can use the retained legacy layout.

`dashboard-grid-demo.html` is a public fictional interaction harness using the same production grid/controller/markup. It makes no account/database request and persists geometry only in its tab session. It is not a substitute for signed-in backend acceptance. Its preview can be constrained to a narrow content width through browser window resizing to review stacking; the real app's private data must not be inserted into this harness.

## Owner correction: simple moving and repeated saves — October 28, 2026

The owner rejected the width/position/visibility form as too much dashboard design and reported that moving one box disabled subsequent moves. The screenshot showed the saved-but-unverified guard. Root cause reproduced: the client compared JSON-stringified objects while retaining their field insertion order, but Postgres JSONB returns the same fields in a different order. Correct positions therefore failed verification. Geometry normalization now constructs fields in a fixed order before comparison; it still rejects different IDs, positions, visibility, identities and timestamps. No save/readback security check was removed.

The design form and width/visibility options are removed. Normal view has Arrange dashboard; arrangement has Done, Undo after a saved change, and Reset layout. Drag remains primary. Clicking one Move handle and then another moves the first box before the second, providing a pointer alternative without a settings form. Alt+arrow controls remain. Genuine uncertain writes still block more saves, show Try again, and permit leaving arrangement mode. Try again reads saved state before resuming; existing geometry/preferences are retained.

Regression coverage now uses database-ordered fields throughout the controller fixture, exercises six sequential moves plus Undo and another move, and compares an actual PGlite JSONB save response using the same client equality function. The prior preview's JavaScript-object field order did not expose this bug; its mock save now returns database-shaped field order. The earlier successful preview checkpoint did not establish signed-in browser persistence and must not be cited as proof of that case.
